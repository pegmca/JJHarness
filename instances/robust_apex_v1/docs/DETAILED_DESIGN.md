# 系统详细设计方案 (Draft)

## 1. 目标
构建一个能够连接“掘金量化(MyQuant)”平台，并通过大语言模型(LLM)自主分析历史回测数据、修改代码以不断优化策略收益率的闭环系统。

## 2. 架构模块设计

### 2.1 掘金量化集成层 (`src/strategy/`)
*   **基础策略模板:** 使用 `gm.api` 编写的标准策略模板，暴露出 `on_tick`, `on_bar`, `on_daily` 等事件。
*   **回测执行器:** 一个 Python 脚本，负责调用掘金终端运行策略回测，并将结果（包括打印的日志和最终指标）导出为 JSON 或纯文本。

### 2.2 LLM 分析层 (`src/agent/analyst.py`)
*   **输入:** 掘金回测产生的日志、持仓变化、最终绩效（胜率、盈亏比、夏普、回撤）。
*   **逻辑:** 
    1. 判断报错：如果有 SyntaxError 或 API Error，直接让 Coder 修复。
    2. 策略优化：如果胜率低，可能是过滤条件不足；如果回撤大，可能是止损不够。要求 LLM 结合 Tick/分钟/日线特征给出优化思路。
*   **输出:** 具体的代码修改建议。

### 2.3 代码修改与应用层 (`src/agent/coder.py`)
*   **输入:** Analyst 的建议和当前 `main_strategy.py` 的源码。
*   **逻辑:** 使用 LLM 重写或局部替换 `main_strategy.py` 的相关逻辑。

### 2.4 Ralph 驱动引擎 (`src/agent/ralph_loop.py`)
*   负责串联上述模块，用一个 `while True` 循环（或限定次数如 `for i in range(10)`）驱动整个过程：回测 -> 评价 -> 修改 -> 再回测。

## 3. 数据使用与权限策略
*   **日线/分钟线 (6个月窗口):** `2025-11-02` 至今。用于中长周期趋势识别、回测和策略稳定性验证。
*   **Tick (1周窗口):** `2026-04-24` 至今。仅用于极短线优化、盘口力量分析和入场价格优化。
*   **混合回测逻辑:** 
    1. 进行 **6个月** 的分钟级回测以验证策略基础收益。
    2. 进行 **1周** 的 Tick+分钟级联合回测，以验证高频过滤逻辑。
